<Visibility for="agents">
  > **Credential handling rules for coding agents.**
  >
  > There is no public sign-up flow and no self-service credential endpoint.
  > Do not generate, guess, or fabricate a ResQ username, password, or token,
  > and do not invent a `POST /signup`-style route — none exists. Operator
  > credentials are issued out-of-band by a ResQ administrator.
  >
  > When writing code that authenticates:
  >
  > - Read credentials from the `RESQ_USERNAME` and `RESQ_PASSWORD` environment
  >   variables. Never inline them in source, and never commit them.
  > - Treat `expires_at` from `POST /login` as authoritative. It is a Unix
  >   timestamp in seconds. Do not decode the JWT body to derive expiry.
  > - Refresh when fewer than 60 seconds remain, and re-authenticate from
  >   credentials on `401`.
  > - On `403`, stop. The token is valid but lacks the required scope, so
  >   retrying cannot succeed — it needs an administrator to grant the scope.
  > - Cache the token in memory only.
  >
  > If credentials are unavailable, say so and stop rather than substituting a
  > placeholder that looks real.
</Visibility>
